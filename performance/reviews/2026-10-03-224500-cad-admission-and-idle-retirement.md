# Admission follow-up: measured workload budgets and idle retirement

Scope: Follow-up to the [first workflow baseline](2026-10-03-220408-workflow-admission-and-token-baseline.md), investigated on 2026-10-03. Historical evidence covers the original 2026-10-02/03 period. The final controlled study ran on 2026-10-03 from 20:40:13 to 20:40:39 UTC at implementation revision `cf66aef`, using CPython 3.12.14 and CadQuery 2.7.0 on Linux/WSL2. The tested source was `model/filament_swatch_box_study/cap_v1_vase_hood_5.py`. Private study admission capacity was four CPUs, 2560 MiB and four jobs; each evaluator requested two CPUs. This is geometry-only tool evidence, not product or print validation.

Measurements: One fresh call initialized the qualified import host. Three subsequent paired evaluations per budget were interleaved, with fresh construction, unchanged source and matching closed-input identities. Pair time includes both evaluator subprocesses completing; overlapping worker durations were not summed.

| Per-call reservation | Median pair elapsed | Maximum queue wait | Maximum sampled worker RSS |
| --- | ---: | ---: | ---: |
| 2048 MiB | 4.475 s | 2.082 s | 291.113 MiB |
| 1024 MiB | 2.670 s | 0.000081 s | 291.234 MiB |

All 13 study executions completed and retained budgets, blocking observations, option-comparison identities and traces. Observed memory blocking totaled 6.078 seconds of queue work; no other blocking reason was recorded. Thirteen new geometry workers shared one import-host initialization (1.768 seconds). A separate ordinary fresh evaluator call used the declared 1024 MiB budget with the normal four-CPU allocation, completed with valid geometry, and sampled 291.082 MiB worker RSS.

Findings: Under the study capacity, two 2048 MiB reservations cannot coexist, whereas two tested 1024 MiB reservations can. The lower reservation reduced median pair latency by 40.3% for this source and operation. This improves scheduling; it does not accelerate CAD kernels. The historical longest wait overlapped a long script and subsequent CAD work, but missing historical capacity/budget observations still prevent assigning its exact limiting resource.

Code inspection also established that the coordinator idle timer counted from request start and ignored queued handlers. Consequently a long request could exhaust the idle allowance before finishing, and pending requests could coexist with an expiration decision. The fix measures idle time after completion and excludes live handlers. Historical reinitialization is consistent with this defect, but no particular old initialization is proven to have this cause.

The installed rollout format uses command argument vectors; the adapter previously classified those items as generic shell activity. Legacy CAD argument fingerprints also omit actual view/export requests. Neither old grouping nor repeated counts establish avoidable work.

Implications: Representative measured reservations can reduce admission delay without overcommitting shared capacity. New geometry workers and cold import initialization are separate observations. Future investigations can distinguish observed CPU, memory, job-slot and resident-memory blocking instead of guessing from elapsed time.

Changes or recommendations: [Execution tools and guidance](../../execution/README.md) now retain bounded admission evidence and full option/budget comparison fingerprints, and correct idle retirement. The evaluator accepts an optional geometry-only memory reservation in the existing execution declaration; it is enabled only for the tested hood source. Explicit command-line budgets take precedence. Rendering, exports, slicing and other models retain the general 2048 MiB CAD default. The adapter accepts vectors without retaining command contents, and the analyzer reports native lease queues separately and labels new/reused geometry workers accurately. Reproduction is documented in [performance guidance](../README.md#targeted-admission-studies); the execution skill owns the measured-budget practice.

Verification and limitations: All 154 affected execution, telemetry, analyzer/privacy, evaluator, slicing, physical-analysis and engineering-question tests passed. All three engineering skills passed validation and local-reference checks. Tests cover queued-handler idle protection, completion-based expiry, cancelled/expired admission, budget stage scope and override, actual coordinator dispatch, overlapping reasons, option identity and private command-vector exclusion. The final study used three pairs per budget; RSS is sampled and includes shared pages, not a hard memory cap or whole-machine peak. Cold setup is excluded from pair medians. No isolated cache-speedup, token-efficiency, unnecessary-verification or broad workload acceleration is claimed. The local analyzer and timeline retained all 13 study executions; this execution-only scope has no agent/token attribution. All raw evidence remains local. The publication scan passed and the text received deliberate factual/privacy review; neither guarantees anonymity.
